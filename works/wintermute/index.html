Engineering details, implementation & lessons learned

Overview

A system to operate, maintain, and learn from.

I designed and maintain an Ubuntu-based homelab supporting containerized applications, private networking, AI workloads, storage services, and infrastructure monitoring. I built the environment to gain hands-on experience with Linux administration, networking, deployment, service orchestration, and operational troubleshooting.

Problem

Shared hardware, connected services.

Running multiple applications on shared hardware requires reliable networking, persistent storage, service isolation, monitoring, and controlled access. As the environment expanded, maintaining those components consistently became an engineering challenge.

Approach

Make configuration and behavior visible.

I organized services using Docker Compose and systemd, configured private access through Tailscale and Technitium DNS, and implemented Caddy reverse proxy routing. I added Prometheus and Grafana for observability and developed Python APIs for system telemetry and operational tooling.

Architecture

Private services, selective public access.

Ubuntu Server 26.04 LTS runs on an AMD Ryzen 7 7800X3D with 32 GB RAM and an NVIDIA RTX 4070 SUPER. Docker networks isolate application traffic, while persistent volumes retain service data.

  • Routing & accessCaddy, UFW, Tailscale, Technitium DNS, and Cloudflare Tunnel provide reverse proxy routing, firewall boundaries, private connectivity, name resolution, and selected public routes.
  • Service operationDocker Compose and systemd define application dependencies and long-running services.
  • ObservabilityNode Exporter and cAdvisor supply infrastructure metrics to Prometheus; Grafana provides monitoring views.
  • Compute & storageContainerized applications, AI inference with NVIDIA CUDA, and storage services share the host.

Technical implementation

Telemetry without administrative access.

I developed a dedicated Python monitoring service that queries Prometheus for CPU, memory, filesystem utilization, and uptime. I deployed it as a restricted systemd service and exposed a sanitized, read-only JSON endpoint through Cloudflare Tunnel, keeping administrative APIs and internal infrastructure private.

I configured container networking, persistent volumes, reverse proxies, and service dependencies, and diagnosed issues involving Docker network attachments, changing container addresses, firewall policies, and upstream connectivity.

Results

An operational self-hosted environment.

The environment supports more than 20 containerized workloads, AI inference, private application hosting, and infrastructure monitoring. I integrated real server telemetry into the public portfolio without exposing Prometheus or privileged management endpoints.

What I learned

Deployment is the beginning.

Operating a system over time requires more than deploying applications. Network boundaries, permissions, monitoring, recovery procedures, and predictable service configuration are essential for maintaining reliable infrastructure. Troubleshooting production-like failures has been particularly valuable in developing practical systems engineering skills.
